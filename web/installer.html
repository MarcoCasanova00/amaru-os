AMARU OS — WebMIDI page (still pre-Indiana)

Test/flash direct-byte WebMIDI path cannot be offered safely today.

I'm following Felucca's loader protocol live in firmware/firmware/src/ota.c: the device itself pulls firmware via its OTA session driven by the host; the host only replies to chunks, guarded by the board-size and 0x11 handshake. I created the logic to attempt a send, but I can't eyeball-verify every instruction against real silicon — sending wrong fragments during a loader attempt can leave the FM-1 in update mode. That is not a brick, but it is a bad user experience, and it's why I still only ship the verifier + THUB install page instead of a local byte stresser.

If you insist on a self-hosted WebMIDI pass, give explicit written OK that you assume all risk, and I will ship one in the next build with the resume+rescue hot-path.
